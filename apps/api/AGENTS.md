# apps/api rules

Root rules ([AGENTS.md](../../AGENTS.md)) apply. This file is what to get right when editing the NestJS API. Conventions: [docs/API.md](../../docs/API.md); testing: [docs/TESTING.md](../../docs/TESTING.md) and [TESTING.md](TESTING.md).

## Layout

- Domain (ShellKeep's own, stays after the retrofit): `src/server-profiles/` (profiles, test connection), `src/terminal/` (`sessions.*` REST, `session-manager.service.ts` tmux lifecycle, `ssh.service.ts`, `terminal.gateway.ts` WebSocket at `/api/terminal/ws`, `tasks/session-cleanup.task.ts` (enqueue-only cron) and `jobs/session-reap.handler.ts` (the `terminal.session.reap` job, #49), `doctor/` and `about/` (the terminal's Doctor checks and About section, #46), `ws/terminal-maintenance.policy.ts` (the maintenance window on the WebSocket)).
- Identity is the platform's since #47 (`src/platform/identity/` binds it; the forked `auth`, `users`, `allowlist`, `device-auth` and `test-auth` modules are deleted). Settings and credentials are the platform's since #48 (`src/platform/settings/`, `src/platform/credentials/`; `app-registrations/settings.ts` and `credentials.ts` hold the namespaces and the `ssh` purpose; the forked `settings` module and `common/utils/encryption.util.ts` are deleted). The host core, About, Doctor and the API reference are the platform's since #46 (`src/platform/host-core.config.ts`, `src/platform/about/`, `src/openapi/`; the forked health, filters, interceptors and middleware are deleted). The job queue and worker-node fleet are the platform's since #49 (`src/platform/jobs/`, `app-registrations/jobs.ts`; the identity housekeeping jobs run on it). Storage is the platform's since #50 (`src/platform/storage/` binds the slice, the profile-image routes and the `storage:import-env` command; `app-registrations/storage-prefixes.ts` holds ShellKeep's key prefixes; the forked `storage` module is deleted). Email and notifications are the platform's since #51 (`src/platform/email/` and `src/platform/notifications/` bind the slices; `app-registrations/notifications.ts` is the manifest of channels, templates and events; `src/notifications-registry/` holds ShellKeep's event registrations, `src/email-templates/` its email templates; the identity notifier bridges to `NotificationsService`). Webhooks and alerts are the platform's since #54 (`src/platform/webhooks/`, `src/platform/alerts/`; ShellKeep's events, starter rules and rule kinds: `terminal/webhooks/`, `terminal/alerts/`). AI is the platform's since #55 (`src/platform/ai/`, `app-registrations/ai.ts`). Still to adopt: `src/common`, `src/prisma`. Do not extend one a later issue replaces (program #30).
- Target layout *(from #44)*: `src/platform/<slice>/` binds each packaged slice (`forRoot` config, host ports); `src/app-registrations/` holds permissions, job labels and other registrations; base modules never import the domain modules.
- `prisma/fragments/` is hand-edited, `prisma/schema/` is GENERATED (`npm run db:compose`), `prisma/migrations/` holds installed platform copies plus the app's own migrations, `prisma/platform.lock` proves them, `prisma/sql/` holds operator scripts (`create-app-role.sql`).
- Tests in `test/` and beside sources (`*.spec.ts`); config `test/jest.config.js`.

## Rules

- **Every route declares its access** (`@Auth(...)` or `@Public()` from `@marinoscar/platform-api/identity`; take the request's organization with `@CurrentOrg()` and name it next to the owner in every query of an org-stamped table). A UI card's permission must equal the string enforced here. Add new routes to RBAC coverage.
- **Validate input** (Zod from #41; DTO classes until then). Document with `@ApiOperation` / `@ApiResponse`.
- **WebSocket gateway**: while a maintenance window is open, refuse a NEW `auth` or `connect` with `{ type: 'auth_fail', reason: 'maintenance' }` (`TerminalMaintenancePolicy`) and leave open sockets alone; authenticate on the first `auth` message through `TerminalPrincipalResolver` (never a query string), require `sessions:write`, end the socket with `auth_expired` at the token's `exp` unless the client re-sends `auth`, re-authorize per message against the session or profile owner, validate every message shape, bound message size and rate, and clean up the tmux/SSH resources on disconnect. Never log terminal payloads.
- **SSH (`ssh.service.ts`)**: all connections go through one factory; host keys are verified before any command runs (#60); decrypted credentials exist only inside the call and never reach a log, span, error message, response, AI prompt or job payload. A profile's secrets are read and written only through `UserCredentialsService` (purpose `ssh`, names `profile.<id>.<field>`, `server-profiles/ssh-credentials.ts`); never name `ENCRYPTION_KEY` outside `server-profiles/migrate/`.
- **Long-running work is a queue job** (root queue rules, in force since #49). Interactive terminal I/O is not a job. A `@Cron` only enqueues.
- **AI** (root AI rules, applies from #55): `AiService.forUser`; redact terminal output before any model call and honour the per-profile AI switch (#56); `ai.*` jobs are server-only.
- **RLS clients** (from #45): `forOrg`/`runInOrg` for org tables, never a `forOrg` client inside `$transaction`; `set_config(..., true)` only.
- **`notify()` after commit**, outside any `$transaction`. A new event is a registration in `src/notifications-registry/`, a template in `src/email-templates/`, a line in `app-registrations/notifications.ts` (the platform/ folders are base code and may not name the domain), and the call site; see the `add-notification` skill. Event keys, channel ids and template names are permanent. The runbook events register only through `registerRunbookNotifications()`.
- **Never hand-edit `prisma/schema/`** once generated; use `npm run prisma:*`, never bare `npx prisma`. Never rewrite an applied migration.
- **No env vars for runtime-configured features** (storage, AI, VAPID, SMTP). App variables go in `.env.example` as documented in root AGENTS.md.
- **A behaviour change carries tests**; run `npm test` and `npm run typecheck` in this folder.
